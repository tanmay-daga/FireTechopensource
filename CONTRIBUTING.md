# Contributing to Bug Buster

Thanks for helping! This is an open-source project and contributions are welcome.

## Ground rules

- Fork the repo and open pull requests from your fork. Please do not spam issues, PRs or comments.
- Keep PRs small and focused, with a clear description of what changed and why.
- Use clear commit messages, for example `fix: reject symlinked paths in scanner`.
- **Never commit secrets** (API keys, tokens, `.env` files). The project needs none.
- Credit any library, dataset, template or code you borrow, and make sure its licence is compatible with MIT.
- Core principle: **everything stays local and patches are never auto-applied.** Changes that add cloud AI calls or auto-apply behaviour will not be accepted.

## Development setup

See the Quick start in the [README](README.md). Backend: `backend/` (FastAPI). Frontend: `frontend/` (plain HTML/CSS/JS, no build step).

## Reporting bugs

Open an issue with: what you did, what you expected, what happened, your OS, Python and Ollama versions, and any backend error text.

## Code of Conduct

By participating you agree to follow the [Code of Conduct](CODE_OF_CONDUCT.md).

# 🐛 Contributing to BUG BUSTER

<p align="center">

**Hunt Bugs. Generate Fixes. Make Development Easier.**

</p>

Thank you for your interest in contributing to **BUG BUSTER**! 🚀

BUG BUSTER is an open-source, AI-powered visual bug detection project that aims to transform software bug screenshots into actionable debugging insights and potential code fixes.

Whether you're a beginner, experienced developer, designer, tester, or open-source enthusiast, **your contribution matters!**

---

## 🌟 Why Contribute?

By contributing to BUG BUSTER, you can:

- 💡 Help build smarter debugging tools.
- 🤖 Improve AI-powered visual bug detection.
- 🎨 Make the user interface more attractive and user-friendly.
- ⚡ Improve application performance and reliability.
- 🔍 Help identify and resolve software issues.
- 🌍 Become part of an open-source community.

## 🛠️ Ways to Contribute

There are many ways to make BUG BUSTER better:

| Area | Contribution |
|---|---|
| 🐛 Bug Fixes | Identify and resolve existing issues |
| ✨ Features | Suggest and develop new functionality |
| 🎨 UI/UX | Improve design and user experience |
| 🤖 AI Integration | Enhance bug analysis and fix generation |
| ⚡ Performance | Improve speed and reliability |
| 📚 Documentation | Improve project guides and explanations |
| 🧪 Testing | Test features and report problems |

## 🚀 Getting Started

Ready to contribute? Follow these steps:

1. **Explore:** Visit the BUG BUSTER GitHub repository.
2. **Fork:** Create your own copy of the repository.
3. **Clone:** Bring your fork to your local development environment.
4. **Understand:** Explore the project structure and existing functionality.
5. **Contribute:** Make your improvements or fix an issue.
6. **Test:** Check that your changes work correctly.
7. **Submit:** Create a pull request for review.

## 📌 Contribution Guidelines

To keep the project organized and maintainable, please follow these guidelines:

- Keep your contributions clean, simple, and meaningful.
- Follow the existing coding style and project structure.
- Avoid unnecessary changes to unrelated files.
- Test your changes before submitting them.
- Write clear and descriptive commit messages.
- Provide sufficient details when submitting a pull request.
- Never upload passwords, API keys, or private credentials.

## 🐞 Reporting a Bug

Found something that isn't working correctly? Help us squash it!

When creating a bug report, include:

- A descriptive issue title.
- A clear explanation of the problem.
- Steps to reproduce the issue.
- Expected behavior.
- Actual behavior.
- Screenshots or error messages, if available.

**The more details you provide, the easier it is to investigate and fix the issue.**

## 💡 Suggesting New Features

Have an idea that could make BUG BUSTER even better?

We would love to hear it!

Please include:

- A short description of your idea.
- The problem it aims to solve.
- Why the feature would be useful.
- How it could improve the user experience.

Creative ideas and fresh perspectives are always welcome!

## 🔄 Pull Request Guidelines

Before submitting your pull request, make sure that:

- Your changes are complete and tested.
- Your contribution follows the project guidelines.
- Your pull request has a meaningful title.
- You have explained what was changed and why.
- Related issues are mentioned, if applicable.

Every pull request will be reviewed by the project maintainers. Suggestions and improvements may be requested before merging.

## 🤝 Community Code of Conduct

We believe open source should be welcoming to everyone.

As a contributor, please:

- Respect all community members.
- Be friendly and supportive.
- Welcome beginners and new ideas.
- Give constructive feedback.
- Respect different opinions and perspectives.
- Maintain a positive and inclusive environment.

Let's build something amazing together!

## 🔐 Security Guidelines

Security is important to us.

- Never expose passwords, API keys, or access tokens.
- Do not upload confidential project information.
- Report security vulnerabilities privately to the project maintainers.
- Avoid sharing sensitive security details in public issues.
